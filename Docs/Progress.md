- **M4 Tasks + broker — VERIFIED (logic + real CLI), UI unchecked:**

  - Tests: DAG validation, order enforcement, verified/failed/no-check outcomes, routed message appears in the target's stream. Real run: Queen (haiku) → ask → plan → approve → assign → real worker wrote `hello.txt` → app ran `grep -qx hi hello.txt` → verified.

Checks run with the user's shell permissions, so the plan approval screen is the safety point (the UI shows the plan, but does not yet highlight check commands specially). - **M6 Skills — VERIFIED (logic + real CLI), UI unchecked:**
  - **Discovery behaviour verified first** on claude 2.1.319 and written to `T2 §3.1`. It corrected one assumption: `--add-dir` duplicates are kept as `<dir>:<name>`, not "first wins". Direct Write/Edit into `<project>/.claude/skills` is denied by the hook policy (`skill-protected`); Bash commands that touch it ask the user.
  - Assignment: `assign_task` accepts `skills`. Workers assigned no skills keep Claude's normal discovery. Unknown skill name → error, no worker started.
  - Versions: first managed change stores a baseline of the pre-existing content; later edits made outside the app are snapshotted before the next change; restore (user click) recreates an old version and is recorded as a new version, so history is never lost.

- **M8 Office — VERIFIED (derivation, layout, CPU, rendered image), interactive UI unchecked:**
  - `shared/office.ts` is a **pure** function from real inputs (session status/paused, tasks, pending approvals, open alerts, delivered routed messages in the last 60 s, last stream event) to characters. Each character carries the **evidence string** for its state; the tooltip, list view and inspector show it. States: working, thinking, waiting, idle, blocked, meeting, completed, error. Priority: error > completed > waiting > blocked > meeting > working/thinking > idle. Working = a tool call is the latest event; thinking = session working otherwise. Meeting = a *delivered* message between two real sessions inside the window (app notices, undelivered, stale, unknown-endpoint and self messages are not meetings). Only Queen + the run's task assignees are drawn.
  - Rooms: Queen's office, desks with task status bar and id, meeting room (count of real meeting participants; 6 seats, overflow stays at the desk but is still labelled), shared workspace (count of real file changes in the last 5 min). Canvas 2D, pixel sprites drawn in code, no assets.
  - Interaction (click a character, or "Inspect" in the **list view**, which shows the same data and is the non-visual alternative; canvas has an aria-label, and each character is a real `<button>`): task and scope, reason, open session, pause/resume, stop, assigned skills, terminal (recent Bash commands + result snippet), routed messages, recent file activity.
  - Tests (12): every state maps to inputs; empty inputs = no characters; idle session with a stale tool event is not "working"; priority; meeting rules; determinism; layout inside the canvas, no overlap with 20 workers; store queries; FrameLoop schedules **no frames** when idle/hidden, is throttled, cancels when work ends.
  - **Measured** (Electron 45, real rAF, hidden window): all-idle office = 0 frames in 5 s, ~0.0% CPU (renderer/GPU/browser); 8 animated agents = 57 frames in 5 s (~11 fps), ~0.2% renderer and ~0.2% GPU CPU. Static state is painted once on every data change.
  - **I looked at the rendered canvas** (headless Electron screenshot of a scenario containing all eight states). It exposed one bug, fixed: task status bars floated in the meeting room under non-seated characters.
  - **Limits:** the full React view (buttons overlay, inspector, panel layout, App integration) compiled and launched but was not screenshotted or clicked; only the canvas drawing was. Frame-to-frame animation is minimal (bob, typing arms, blinking glyphs). "Thinking" is inferred from status + last event, not from model internals. Office shows one Queen run at a time. No "collaboration areas" beyond the meeting room and the shared-workspace strip. The terminal view is derived from Bash tool events (no live PTY, no interrupt).

## How to run

`cd app && npm run dev` · `npm test` · `QUEEN_REAL=1 npm test` (uses a few cents-equivalent of your own subscription window).
